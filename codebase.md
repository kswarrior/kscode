# KS Code - Codebase Map & Flows
This document is the authoritative map of every source file in the KS Code
repository together with short notes on what each file does, followed by a
description of the main runtime flows (file editing, shell execution, AI
agentic chat, settings, projects, chats, terminals).

## 2. Backend file notes

### backend/go.mod
- Module name `kscode`, Go 1.25.
- Zero external dependencies; uses only the Go standard library
  (incl. a hand-written WebSocket implementation in `internal/ws`).

### backend/cmd/server/main.go - entrypoint
- **Listen address resolution (in order):** `--port` flag > `KS_PORT` env >
  `KS_ADDR` env > default `:6060`.
- Resolves runtime dirs relative to the executable: `<exe>/workspace` and
  `<exe>/data` when the corresponding env vars are unset.
- Builds config store, settings store, fs service, shell manager, projects
  store, chats store, LLM client, tools manager and agent task manager.
- `rootFn` returns the active project's path when one is open, otherwise the
  workspace dir; it is the sandbox root for the files + tools APIs.
- Constructs all 8 API handlers and wires them into one `http.ServeMux` via
  `api.New`, mounting `/api/` plus an SPA handler at `/`.
- Serves the **embedded frontend** (go:embed) when `KS_STATIC` is unset.
- Wraps the root handler in CORS -> Recoverer -> Logger middleware.
- Graceful shutdown on SIGINT/SIGTERM (http.Server.Shutdown).

### backend/internal/config/config.go - configuration
- `Config` holds `Addr`, `WorkspaceDir`, `StaticDir`, `APIDir`,
  `FrontendOrigin`, `AllowedOrigins`, `Env`.
- `Default()` reads env vars (KS_ADDR default `:8080`, KS_WORKSPACE,
  KS_STATIC, KS_API_DIR, KS_FRONTEND_ORIGIN, KS_ALLOWED_ORIGINS).
- **Known discrepancy:** `config.Default()` defaults `Addr` to `:8080`
  (README + vite proxy target :8080), but `main.go`'s resolution chain falls
  back to `:6060` when no env/flag is set. Running bare `./kscode` listens on
  :6060; running via `KS_ADDR=:8080` matches the docs/proxy.
- `Store` is a thread-safe JSON-backed persistence layer for the config file;
  `Get()` returns a deep copy, `Update(fn)` mutates under a write lock.

### backend/internal/fs/service.go - file system operations
- Sandboxed at `root`: `Resolve()` cleans every path and rejects any that
  escape the root (`..` / absolute paths outside), so the API cannot touch
  arbitrary disk paths.
- `Tree(path, depth)` builds a recursive `Entry` tree (`Name/Path/IsDir/
  Size/ModTime/Children`, dirs first, hidden files skipped).
- `Read` returns content + detected language for the Monaco editor.
- `Write` creates parent dirs and writes a file (MkdirAll + WriteFile).
- `Mkdir`, `Delete` (refuses to remove the root), `Rename` (with re-expanded
  children), `Upload` (multipart), `Search`.
- `Search(query, max)` walks the tree skipping .git/node_modules/dist and
  returns `{path, line, preview}` matches; skips files > 2 MB.
- `detectLanguage` maps extensions (go/ts/js/json/yaml/...) to Monaco ids.

### backend/internal/shell/service.go - PTY shell sessions
- `Manager` keeps a `map[string]*Session` keyed by random hex id.
- `Session` holds `{ID, Cmd, master *os.File (PTY master), closed, rows/cols,
  cwd, name, cancel, listeners, history []Event}`.
- `Start(opts{Cols,Rows,Cwd,Shell,Name})` spawns `$SHELL` (default /bin/bash)
  on a **real PTY** (Linux `/dev/ptmx` via `pty_linux.go`); emits a `start`
  event with the PID.
- `pumpPTY` reads the PTY master and emits `data` events (all labeled
  `stdout`; stderr keeps xterm's red coloring via ANSI escape passthrough).
- `history` retains recent events so a **late-connecting client** (reopen /
  reconnect) receives buffered output, not just an empty screen.
- `Resize(rows, cols)` records size and calls `TIOCSWINSZ` so line editors
  (readline) re-flow; exits are broadcast as `exit` events and the session
  is removed.
- `List()` returns `[]SessionInfo{ID,Name,Cwd,PID,Alive}`; `SetName` renames;
  `Kill(id)` SIGKILLs the session.
- `Subscribe()` returns a channel + unsubscribe func; used by the WS handler.
- Non-Linux builds (`pty_other.go` build tag) get a stub that returns
  `"pty: only supported on linux"`.

### backend/internal/settings/service.go - settings + API keys
- `Settings = {AI:{defaultProvider, providers[]}, UI:{theme, fontSize,
  tabSize, wordWrap, minimap}}`; `Provider{ID,Name,BaseURL,APIKey,Enabled,Models}`.
- `Default()` seeds four providers: Gemini, NVIDIA NIM (3 models), OpenAI,
  Anthropic, each with canonical base URLs and default models.
- UI defaults: theme `vs-dark`, fontSize 14, tabSize 2, wordWrap true,
  minimap false.
- `Store` persists to `$KS_API_DIR/settings.json` with mode 0600.
- `UpsertProvider`/`DeleteProvider`/`UpdateProviderModels` mutate by id;
  `KeyFor(id)` is what the LLM client uses to fetch a key at call time.

### backend/internal/projects/service.go - project management
- `Project = {ID, Name, Path, CreatedAt}`; stored in `$KS_API_DIR/projects.json`
  (0600), with `activeID` persisted separately.
- `Store` with thread-safe mutex; `List()`, `Get(id)`, `Add(name, path, create)`,
  `Rename(...)`, `Remove(id)`, `Active()`, `SetActive(id)`.
- `Add` deduplicates by absolute path; when `create=true` the path is
  mkdir -p'd; the added project becomes a candidate for `Active()`.

### backend/internal/chats/service.go - chat history
- `Chat = {ID, Title, CreatedAt, UpdatedAt, Model, Provider, Messages[]}` per
  project; `Message{Role, Content, ...}` may carry `Tools []MessageTool`.
- `MessageTool{ID, Name, Args, Result{OK, Output}}` persists **tool calls and
  results** so the UI can re-render tool cards after reopening a chat.
- Persisted to `$KS_API_DIR/chats.json` (0600) as `map[projectID][]Chat`.
- `List(projectID)` newest first; `Create(projectID)` ("New chat" title);
  `Rename`; `SetMeta(provider, model)`; `AppendMessage(role, content)`;
  `UpsertAssistant(...)` (updates/replaces the last assistant message,
  incl. tool results); `Remove`; `RemoveProject`.
- `AppendMessage` auto-derives the title from the first user message when the
  title is still the default. Thread-safe + persists on every mutation.

### backend/internal/llm/client.go - LLM forwarding
- `Client` wraps `*settings.Store` + `http.Client` (no overall timeout for
  streaming).
- `Chat(ctx, req)` looks up provider + key, then dispatches:
  - `gemini` -> native `generateContent` (`?key=...`)
  - `nvidia`/`openai`/`anthropic`/... -> OpenAI-compatible `/chat/completions`
- `StreamChat(ctx, req, onDelta)`:
  - OpenAI-compatible: SSE `data:` lines -> `Delta{Delta, Done}`
  - Gemini: `streamGenerateContent?alt=sse` -> text parts as deltas
- Falls back to `os.Getenv(providerID + "_API_KEY")` when no key is stored.

### backend/internal/tools/manager.go - agent tools (sandboxed)
- Package comment enumerates the **13 tools**: shell, read, write, edit,
  multi_edit, patch, mkdir, delete, rename, glob, grep, ls, list_files.
- `Manager` is constructed with the active project root; `resolve()` rejects
  any path escaping the root (mirrors fs.Service) so the agent cannot read or
  write outside the project.
- `Result{OK bool, Output string}` is returned for every tool; failures are
  surfaced as `OK:false` with the error text rather than panicking the loop.

### backend/internal/agent/ - agentic run loop
- **run.go** - provider-agnostic tool-call loop: the model's reply is scanned
  for fenced ```` ```tool_call ``` ```` JSON blocks (plus lenient bare/inline
  variants, see `parser_test.go` / `literal_nl_test.go`), each call is executed
  via `tools.Manager`, and the results are fed back to the model until it
  finishes (or `MaxRounds` is hit).
  - Emits SSE events tagged `thinking`, `assistant_delta`, `tool_request`,
    `tool_result`, `retry`, `done`, `error`.
- **task.go** - `BackgroundTask` holds `{ID, Provider, Model, System, Cwd,
  Messages, MaxRounds, Status, Events[], FinalText, Error, CreatedAt,
  UpdatedAt, CancelFunc}`; `TaskStatus` = pending|running|completed|stopped|
  error. `TaskEvent{Event, Timestamp}` timestamps every event for replay.
  `TaskManager` tracks all tasks; `Stop(id)` cancels via `CancelFunc`.
  Tasks are kept so the stream endpoint can replay after a reconnect.
- **prompt.go** - `SystemPrompt` teaches the model CHAT vs ACT modes and the
  tool-call protocol (fenced blocks, argument schema).

### backend/internal/ws/conn.go - WebSocket server
- Self-contained RFC6455 server (no gorilla/websocket): handshake via
  SHA-1 + base64 of `Sec-WebSocket-Key` + magic GUID, `ReadFrame` handles
  7/16/64-bit lengths + client masking, `Write` sends server frames.
- `ParseKey(header)` accepts a raw header block or a single `header.Get`
  value. Used by the shell WebSocket (`/api/shell/ws`).

### backend/internal/web/embed.go - embedded frontend
- `//go:embed all:dist` embeds `backend/internal/web/dist` (a copy of the
  built frontend) into the binary; `FS()` exposes it to the SPA handler.
- Dist assets are hashed; the embedded copy is currently fresher than
  `frontend/dist` (`index-BXTVspzx.js`/`index-B_MwY8qI.css` vs
  `index-BZgDe7y-.js`/`index-Bwo84prX.css`) and must be refreshed after any
  frontend rebuild (rebuild.sh copies `frontend/dist` -> `backend/internal/web/dist`).

### backend/internal/api/router.go
- `New(fsH, shellH, settingsH, llmH, workspaceH, projectsH, chatsH, agentH)`
  instantiates one `http.ServeMux` and calls `Register(mux)` on each of the
  8 handlers (agent handler registered last).

### backend/internal/api/middleware.go
- `statusRecorder` captures status + bytes and **passes through `Hijacker`
  and `Flusher`**, so WebSocket upgrades and SSE streams (`/api/llm/stream`,
  `/api/agent/run`) keep working under `Logger`.
- `Logger` logs `METHOD path -> status bytes duration`; `Recoverer` turns
  panics into 500 JSON; `CORSMiddleware` reflects the Origin from an
  allow-list (or `*` when empty) and short-circuits OPTIONS with 204.
- `Chain` composes middlewares outside-in.

### backend/internal/api/util.go
- `writeJSON` / `writeError` / `parseJSON` (uses `DisallowUnknownFields`),
  `methodNotAllowed`.

### backend/internal/api/workspace.go
- `GET /api/health` -> `{status, time, uptime}`.
- `GET /api/workspace` -> `{root, apiDir, staticDir}`.

### backend/internal/api/files.go
- `NewFilesHandlerFromRoot(rootFn)` lazily resolves the per-request root via
  `rootFn()`, so switching projects switches the FS sandbox.
- `GET /api/files/tree?path=&depth=`, `GET /api/files/read?path=`,
  `POST /api/files/write`, `POST /api/files/mkdir`, `POST /api/files/delete`,
  `POST /api/files/rename`, `GET /api/files/search?q=`.
- `GET /api/files/download?path=`, `GET /api/files/download-zip?paths=`,
  `GET /api/files/download-project` (whole project), `POST /api/files/upload`
  (multipart), `POST /api/files/upload-url` (returns URL for direct upload).

### backend/internal/api/shell.go
- `POST /api/shell/start` body `{cols, rows, cwd?, shell?, name?}` ->
  `{id, pid, cwd}`; mints a session id and spawns the PTY shell.
- `GET /api/shell/ws?id=` upgrades to WebSocket and bridges inbound
  `{type:'input'}` / `{type:'resize'}` / `{type:'ping'}` and outbound events.
- `GET /api/shell/list` -> `[]SessionInfo`; `POST /api/shell/stop` body
  `{id}`; `POST /api/shell/rename` body `{id, name}`.

### backend/internal/api/settings.go
- `GET /api/settings`, `POST /api/settings` (validated replace).
- `POST /api/settings/providers` (upsert one provider), `POST
  /api/settings/providers/delete` body `{id}`, `GET
  /api/settings/providers/models` (default models per provider).

### backend/internal/api/llm.go
- `POST /api/llm/chat` -> forwards to `llm.Client.Chat`, returns
  `{provider, model, content, raw?}`; missing key / upstream errors -> 502.
- `POST /api/llm/stream` -> SSE: `data: {"delta":"..."}` per token,
  `data: {"done":true}` on completion, `data: {"error":"..."}` on error.
  (Superseded for interactive chat by the agent endpoints, but kept as a
  direct path.)

### backend/internal/api/projects.go
- `GET /api/projects` -> `{projects}`; `POST /api/projects` `{name, path,
  create?}` (dedupes by path).
- `GET /api/projects/active` -> `{project|null}`; `POST
  /api/projects/active` `{id}`; `POST /api/projects/rename` `{id, name?,
  path?, create?}`; `POST /api/projects/delete` `{id}` (cascades to chats).

### backend/internal/api/chats.go
- `GET /api/chats?projectId=`, `GET /api/chats/one?projectId=&chatId=`,
  `POST /api/chats/create` `{projectId}`, `POST /api/chats/rename`,
  `POST /api/chats/append`, `POST /api/chats/upsert` (replace last assistant
  message incl. tool results), `POST /api/chats/meta`, `POST
  /api/chats/delete`. All validate ids and return 400/404 accordingly.

### backend/internal/api/agent.go
- `NewAgentHandler(client, rootFn)` builds the handler with an
  `agent.TaskManager`.
- `POST /api/agent/run` body `{provider, model, messages, maxRounds?}` ->
  returns `{taskId}` **immediately**; the run proceeds in a background task.
- `GET /api/agent/stream?taskId=` -> SSE replay of stored events (`thinking`,
  `assistant_delta`, `tool_request`, `tool_result`, ..., `done`); reconnects
  resume from the task's event log.
- `POST /api/agent/stop` body `{taskId}` -> cancels the running task.

## 3. Frontend file notes

### frontend/package.json
- `type: module`; scripts: `dev`, `build` (`tsc --noEmit && vite build`),
  `preview`, `typecheck`.
- Runtime deps: `react` 18.3, `react-dom`, `@monaco-editor/react ^4.6.0`,
  `@xterm/xterm ^5.5.0`, `@xterm/addon-fit ^0.10.0`.
- Dev deps: `vite`, `@vitejs/plugin-react`, `typescript`, `@types/react(-dom)`.

### frontend/vite.config.ts
- React plugin, output to `dist` (emptyOutDir).
- Dev server on :5173 proxying `/api` -> http://localhost:8080 **with
  `ws:true`** so the shell WebSocket is forwarded too.

### frontend/src/types/index.ts
- Mirrors backend JSON shapes: `FileEntry`, `FileContent`, `SearchResult`,
  `Provider`, `AISettings`, `UISettings`, `Settings`, `ShellEvent`,
  `ShellStartResponse`, `ShellSession`, `ChatRequest`, `ChatResponse`,
  `Project`, `Chat`, `ChatMessageTool`, `AgentEvent`, `AgentRunRequest`.

### frontend/src/api/client.ts
- `req<T>(path, init)` helper: `fetch(BASE + path)` with JSON content-type,
  throws `Error(body.error | HTTP n)`.
- `api` groups every endpoint: `projects` (list/add/rename/remove/active/
  setActive), `chats` (list/one/create/rename/append/upsert/meta/remove),
  `files` (tree/read/write/mkdir/remove/rename/search/download/upload),
  `settings` (get/save/upsertProvider/deleteProvider/updateProviderModels),
  `shell` (start/list/stop/rename/wsUrl), `agent` (run/stream/stop), `llm`
  (chat/stream).
- `shell.wsUrl(id)` builds the WS URL from `window.location` (works under the
  dev proxy and same-origin prod). `llm.stream` and `agent.stream` consume
  SSE via fetch `ReadableStream` (`onDelta`, resolve on done, reject on error).

### frontend/src/hooks/useWorkspace.ts
- State: root + tree + loading + error; `refresh(path)` calls
  `api.files.tree`, auto-runs on mount. Returns `{root, tree, loading, error,
  refresh}` for the FileTree.

### frontend/src/hooks/useSettings.ts
- **Module-level shared store** built on `useSyncExternalStore`: loaded once,
  shared by every component (WorkspaceLayout, Editor, Settings, ChatPanel).
- `applyUI(ui)` applies theme/fontSize/tabSize/wordWrap/minimap instantly;
  `save`, `upsertProvider`, `deleteProvider`, `updateProviderModels` sync with
  the server.

### frontend/src/hooks/useProjects.ts
- State: `projects[]`, `active`, loading, error. `reload()` fetches list +
  active. `add(name, path, create)`, `rename(id, patch)`, `remove(id)`,
  `open(id)` each hit the projects API then reload.

### frontend/src/hooks/useChats.ts
- Per-project chat list + active chat. On project change, reloads chats and
  restores the last active chat id from `localStorage` key
  `kscode:activeChatId`.

### frontend/src/hooks/useTerminals.ts
- Terminal session list + active terminal; persists active session id in
  `localStorage` key `kscode:activeTerminalId`; exposes a `clearTermRef`
  pattern so the active terminal can clear/ref its session. Terminals are
  **not** scoped per project (PTY sessions live server-side).

### frontend/src/components/Icon.tsx
- Shared stroke-based SVG icon set: Menu, Files, Search, Chat, Settings,
  ChevronDown/Right, Close, Edit, File, Folder, FolderOpen, Plus, Trash,
  Download, Upload, Link, Refresh, MoreVertical, Check, Spinner, Stop, Tool,
  Send, Terminal, Erase, Logo, Sparkle.

### frontend/src/components/Menu.tsx + Dropdown.tsx + DropdownMenu.tsx
- `Menu`: keyed item list (align left/right, outside-click/Escape close).
- `Dropdown<T>`: generic select with value/label/options, outside-click close.
- `DropdownMenu`: item menu (label/onClick/icon/disabled/danger/divider)
  opened from a 3-dot trigger; used by FileTree and ProjectDropdownMenu.

### frontend/src/components/Layout/WorkspaceLayout.tsx(.css)
- App shell: top header (brand + nav icons), left sidebar, main area.
- **Main page switching** via header icons: `MainPage` =
  `"chat" | "editor" | "settings" | "terminal"` (chat is the default).
- Sidebar content follows the page: chat -> `ChatsList`, terminal ->
  `TerminalsList`, editor -> `FileTree`; settings renders in the main area.
- Wires `useWorkspace` + `useSettings` + `useProjects` + `useChats` +
  `useTerminals`; on active-project change re-fetches the tree.
- Mobile responsive: hamburger menu turns the sidebar into a drawer.

### frontend/src/components/FileTree/FileTree.tsx(.css)
- Recursive `TreeNode` (expanded state, icon, folder toggle, file open).
- Row hover reveals inline rename/delete/upload plus a `DropdownMenu`
  (download, download-zip, download-project, upload, upload-url, rename,
  delete).
- New file/folder via `FileDialog`; all mutations call `api.files.*` then
  `onRefresh()`.

### frontend/src/components/FileTree/FileDialog.tsx(.css)
- Modal for new file / new folder; validates the name (rejects
  `< > : " | ? *`) and shows server errors inline.

### frontend/src/components/Editor/Editor.tsx(.css)
- Wraps `@monaco-editor/react`; loads via `api.files.read` on path change,
  tracks `dirty` against the saved snapshot.
- Saves on Ctrl/Cmd+S (Monaco command + global window handler that ignores
  the event when an xterm has focus), toolbar Save button too.
- Options (theme, fontSize, tabSize, wordWrap, minimap) come from settings.

### frontend/src/components/Terminal/Terminal.tsx(.css)
- Xterm.js `Terminal` + FitAddon; props `cwd/fontSize/sessionId/autoStart/
  onExit/onRegisterClear`.
- `Start` -> `api.shell.start({cols, rows, cwd})`, opens WS to
  `api.shell.wsUrl(id)`, bridges `term.onData` <-> `{type:'input'}`, handles
  `data` (stderr kept red via ANSI passthrough) and `exit` banner.
- `hardClear()` writes `\x1b[H\x1b[2J\x1b[3J` (clears scrollback too).
- Reconnect: with `sessionId` set it can rejoin an existing server session;
  window resize -> `fit.fit()` + WS `resize`.

### frontend/src/components/Terminal/TerminalsPanel.tsx(.css)
- Main terminal area; renders the active `Terminal` (cwd = active project
  path, else workspace root). Reuses `chats-panel` / `chats-conversation`
  CSS classes from ChatsPanel.css for consistent layout.

### frontend/src/components/Terminal/TerminalsList.tsx(.css)
- Sidebar list mirroring `ChatsList` ("Terminals" title + New button); each
  session is a list item, active is highlighted; clicking selects it.

## 4. Runtime flows

### Flow A - Open and edit a file
1. App mount -> `useWorkspace` calls `api.files.tree('/')` -> FileTree renders.
2. User clicks a file node -> `onOpen(path)` sets `activePath` in
   WorkspaceLayout (editor page).
3. `<CodeEditor filePath=...>` effect fires `api.files.read(path)` -> Monaco
   loads content.
4. User types -> `onDidChangeModelContent` sets `dirty=true`.
5. Ctrl+S -> `api.files.write(path, content)` (guarded when xterm focused) ->
   dirty=false.

### Flow B - Run a shell command (PTY)
1. Terminal page -> `TerminalsPanel` mounts xterm (FitAddon).
2. Start -> `api.shell.start({cols, rows, cwd, name})` -> backend spawns
   $SHELL on a real PTY (`/dev/ptmx`).
3. UI opens WS to `/api/shell/ws?id=`; sends `{type:'input'}` and
   `{type:'resize'}`; receives `data`/`exit` events.
4. Server pumps PTY master -> stdout events (ANSI/color preserved); resize
   calls `TIOCSWINSZ` so readline reflows.
5. On process exit -> `{type:'exit', exit:...}`; session removed from manager.
6. If the WS drops, `history` lets a later reconnect replay recent output.

### Flow C - AI agentic chat (tool loop)
1. Chat page -> ChatPanel sends POST /api/agent/run; the server mints a
   `taskId` and returns it immediately.
2. The background task runs the model with the agent system prompt (ACT
   mode), streaming events over GET /api/agent/stream?taskId= (SSE):
   `thinking`, `assistant_delta`, `tool_request`, `tool_result`, `retry`,
   `done`.
3. On `tool_request` the loop executes the fenced `tool_call` JSON through
   `tools.Manager` (sandboxed to the active project root) and feeds the
   result back; repeats until done / MaxRounds.
4. ChatPanel renders deltas + tool cards live; Stop calls
   `api.agent.stop`; the turn is persisted via `api.chats.append`/`upsert`
   (including tool results) so cards survive reload.

### Flow D - Direct LLM streaming (non-agent path)
1. `api.llm.stream(req, onDelta)` -> POST /api/llm/stream with `stream:true`.
2. Backend `llm.Client.StreamChat` (OpenAI-compat SSE or Gemini
   `streamGenerateContent?alt=sse`).
3. `data: {"delta":"..."}` -> `onDelta`; `done` resolves, `error` rejects.

### Flow E - Settings & API keys
1. `useSettings` GETs /api/settings on module load (seeds defaults).
2. Settings page tabs edit UI prefs / providers (add/edit modal, models
   field, connect dropdown).
3. 'Save Key' upserts one provider immediately; 'Save Settings' POSTs the
   whole object -> backend validates + rewrites settings.json (0600).
4. Keys are read server-side via `settings.Store.KeyFor` at call time; chat /
   agent flows never receive the raw key in the browser.

### Flow F - Project management
1. `ProjectDropdownMenu` (top of chat page) shows active project; click
   switches via `projects.open(id)`.
2. Active project change reloads the file tree (new sandbox root), reloads
   chats, and re-points the terminal cwd.
3. Add / Rename / Edit / Delete via `ProjectFormDialog` + 3-dot menu; delete
   cascades to the project's chats.

### Flow G - Chat history per project
1. Chat page -> `useChats` loads the active project's chats; last active chat
   restored from localStorage (`kscode:activeChatId`).
2. "New chat" -> `api.chats.create`; click -> `ChatPanel` renders conversation.
3. Streaming/agent turns persist via `api.chats.append`/`upsert`; provider/
   model remembered via `api.chats.meta`.
4. Rename inline in the list; delete -> list refreshes.

### Flow H - Terminals
1. Terminal page -> `useTerminals` lists server sessions (`api.shell.list`);
   active session id in localStorage (`kscode:activeTerminalId`).
2. "New terminal" -> `api.shell.start` -> PTY session (not project-scoped).
3. `Terminal.tsx` bridges xterm <-> WS; `hardClear` clears scrollback;
   reconnect joins an existing server session by id.

### Flow I - File operations (tree)
1. FileTree recursive nodes; hover actions + 3-dot menu: download,
   download-zip, download-project, upload / upload-url, rename, delete.
2. New file/folder via `FileDialog` (name validated against
   `< > : " | ? *`); all mutations call `api.files.*` then refresh the tree.

## 5. Build & run (cheat sheet)
```bash
# One-shot release build (frontend + backend, single binary)
./rebuild.sh                                 # -> release/kscode (serves embedded web)
KS_WORKSPACE=release/workspace ./release/kscode   # http://localhost:6060

# Frontend only
cd frontend && npm install && npm run build   # -> dist/ (tsc --noEmit && vite build)

# Backend only (serves already-embedded web)
cd backend && go build -buildvcs=false -o kscode ./cmd/server
./kscode                                     # default :6060 (see addr note below)

# Dev (two terminals) - proxy targets :8080
KS_ADDR=:8080 go run -buildvcs=false ./cmd/server   # in backend/
npm run dev                                  # in frontend/ -> :5173 (proxies /api -> :8080)

# After a frontend change, refresh the embedded copy before rebuilding Go:
cp -r frontend/dist/. backend/internal/web/dist/
```
> **Address note:** bare `./kscode` listens on `:6060` (main.go fallback).
> `config.Default()`, `vite.config.ts` and `README.md` all expect `:8080`;
> set `KS_ADDR=:8080` (or `KS_PORT=8080`) to match.

## 6. Notable design choices
- **Zero external Go deps**: net/http + a hand-written RFC6455 WebSocket
  (ws/conn.go) keep `go build` self-contained and hermetic.
- **Path sandboxing**: both `fs.Service` and `tools.Manager` reject any
  resolved path escaping the project root, so neither the API nor the agent
  can touch arbitrary disk paths.
- **Real PTY shell**: `pty_linux.go` uses `/dev/ptmx` (TIOCGPTN etc.) with
  `TIOCSWINSZ` resize, giving a faithful interactive terminal (readline,
  ANSI color, resize all behave); non-Linux builds get a stub.
- **Agentic tool loop, provider-agnostic**: the model expresses intent as
  fenced ```` ```tool_call ``` ```` JSON blocks; a lenient parser also accepts
  bare/inline variants (incl. literal newlines in file content), executes them
  sandboxed, and feeds results back - no per-provider tool plumbing.
- **Background tasks + SSE replay**: `/api/agent/run` returns a task id
  immediately; `/api/agent/stream` replays the stored, timestamped event log,
  so reconnects resume cleanly without losing tool-call history.
- **Tool-call persistence**: chats store `MessageTool{ID, Name, Args, Result}`
  so the UI re-renders tool cards after reopening a chat, not just live.
- **Single binary deploy**: the Go process embeds `frontend/dist` via
  `go:embed`; `rebuild.sh` copies the fresh dist into
  `backend/internal/web/dist` before building `release/kscode`.
- **Keys never hard-coded**: stored in settings.json (0600), fetched at call
  time; env fallback `PROVIDER_API_KEY` supported.
- **Project-scoped workspaces**: the active project determines the FS root for
  file operations and agent tools, plus chat history; terminals are global
  PTY sessions.
- **Frontend keeps state live across pages**: module-level `useSettings`
  store + localStorage persistence for active chat / terminal ids.
